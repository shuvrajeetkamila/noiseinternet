# Noise Internet — Android app

**Status: source only. Never compiled, never installed, no APK exists in this repository.** The
environment this project was written in has no JDK, no Android SDK and no NDK, so `gradle` was never run
and no `.apk` was produced or signed (not "debug-signed" either — that would be a claim about a file that
does not exist). Measured state of the whole project: [`../reports/RESULTS.md`](../reports/RESULTS.md) and
[`../docs/STATUS.md`](../docs/STATUS.md).

## Layout

```
android/
  settings.gradle.kts, build.gradle.kts, gradle.properties
  app/build.gradle.kts                        AGP 8.5.2 / Kotlin 1.9.24, ndk r26, minSdk 23
  app/src/main/AndroidManifest.xml             permissions and the service that owns the link
  app/src/main/java/com/noiseinternet/core/NoiseCore.kt      Kotlin surface + PhyTools (external fns)
  app/src/main/java/com/noiseinternet/core/AudioEngine.kt    AudioRecord/AudioTrack float PCM pump
  app/src/main/java/com/noiseinternet/core/NoiseService.kt   foreground service, tunnel, actions
  app/src/main/java/com/noiseinternet/app/MainActivity.kt    the operator panel (plain Activity)
  app/src/main/res/layout/activity_main.xml
  app/src/main/jni/noiseinternet_jni.cpp       JNI forwarders to ni_abi_*
  app/src/main/jni/CMakeLists.txt              compiles ../shared/acoustic_core from source
```

The protocol, DSP, FEC, crypto and ARQ are **not** re-implemented in Kotlin: the app calls the flat C ABI
(`shared/acoustic_core/include/ni/abi.h`) that the Linux CLI and the Windows app also use. If Android and
Windows ever behave differently, the bug is in the binding layer, which is ~250 lines.

## Prerequisites

* JDK 17.
* Android SDK Platform 34 + Build-Tools, and **NDK r26** (`sdkmanager "ndk;26.1.10909125"`).
* CMake 3.22.1 (bundled with the SDK is fine).
* A phone with a working microphone and loudspeaker, and a second device (another phone, or the Windows
  build) running the same protocol version, session id and passphrase.

## Build

```sh
cd android
gradle wrapper --gradle-version 8.7      # if you want the wrapper committed; not shipped here
./gradlew :app:assembleDebug            # -> app/build/outputs/apk/debug/app-debug.apk
./gradlew :app:assembleRelease          # needs your own signingConfig; none is committed
```

`assembleDebug` signs with the standard debug keystore in `~/.android/debug.keystore`. Say so out loud
when you describe the result: **debug-signed, locally installed, not a release signature**.

Install and grant the one runtime permission:

```sh
adb install -r app/build/outputs/apk/debug/app-debug.apk
adb shell pm grant com.noiseinternet.app android.permission.RECORD_AUDIO
adb shell am start -n com.noiseinternet.app/.MainActivity
```

Expected first-build failures, and why they are not surprises: the JNI file has never been through a
compiler (`javac -h` regenerates the header, and the method names must match `NoiseCore`/`PhyTools`), and
AGP plugin/NDK version pairs are picky. Fixing them is normal porting work, not evidence about the
protocol.

## Using it

1. Both ends: same **session id** and same **passphrase**. The passphrase is what derives the session
   keys; the core prints its estimated entropy and refuses short ones in `ni audit`. A 4-word SAS code is
   shown when pairing completes — read it over on both screens to confirm you are talking to the device
   you think you are.
2. Pick **Giver** on the phone with internet and **Receiver** on the other. Start both.
3. Press **Calibrate** on either end first: it sweeps the bands through the real speaker/microphone pair
   and the table lists measured success, BER, b/s and which bands the code considered usable.
4. **Link test** sends a hash-checked payload. It is the only honest way to see whether the link carries
   data at all — until that prints a matching SHA-256, nothing about "internet sharing" is true.
5. **Internet test** asks the giver to fetch a URL and pushes the bytes over sound; the report shows each
   stage (link up, fetch, transfer, CRC, SHA-256) and which one failed.
6. Point a browser on the receiver machine at `http://127.0.0.1:8471` for the proxy path.

## What is intentionally limited

* **The tunnel carries UDP and DNS only.** `NoiseService.openTunnel()` parses outbound IPv4 packets,
  forwards UDP payloads into the link, and injects answers back. TCP is counted and dropped, on purpose:
  a link with ~0.2–2 s bursts and a 1.2 s ack timeout cannot win against a TCP stack's own retransmission
  timers, and pretending otherwise produces a "tunnel" that hangs. Web browsing therefore uses the
  receiver's local HTTP/CONNECT proxy, where this project's own ARQ is the reliability layer.
* **The proxy binds 127.0.0.1 only** and requires a token (`Proxy-Authorization: Noise <token>`,
  generated by the core and printed in the status JSON). Nothing is exposed on a LAN or on the internet,
  and no firewall hole is opened. If you want other machines to use it, that is your network policy
  decision — this code does not make it for you.
* **No root, no kernel module, no VPN "always-on"**: the manifest deliberately omits
  `BIND_VPN_SERVICE` (see the comment there) so the app can own its own service lifecycle.
* **Nothing bypasses a carrier, a captive portal, a firewall or a corporate policy.** Acoustic transfer
  is slow and audible; if a network forbids tethering, this is not a way to hide from that rule. Use it on
  devices you own, on a connection you are allowed to share, and expect a few hundred bytes per second at
  best in simulation.
* **HAL audio processing**: `AudioRecord` tries `UNPROCESSED` first (API 24+) because noise suppression /
  AGC / AEC in the phone's input path destroys a calibrated modem signal. Whatever source was actually
  used, and whatever device the sound was routed to, is printed in the status panel — a run on
  `MIC` with a headset attached is not comparable to a run on `UNPROCESSED` with the built-in speaker,
  and the app says so instead of hiding it.
